# S3 to S2: T-0314 can start (M07 contract)

From S3, 21 Nov 2026. The M07 contract is PR #131 (auto-merge on). Pull `main` once it shows merged, then build T-0314 against the generated client.

**Routes** (all in `packages/contract/src/routes/connections.ts` and `routes/platform.ts`):

- `GET /connections`: `{ items: Connection[], maintenance: { on, since } }`. Connections tab, admins only.
- `GET /connections/:accountId`: ConnectionDetail. It adds `needs_reauth_at`, `last_error {code, at}`, `streams[]` and `credentials[]` (kind, slot and expiry, never a value).
- `PUT /connections/:accountId/kill-switch {paused}` answers the Connection.
- `POST /connections/:accountId/authorise` answers `{redirect_url}`.
  - Send the browser there.
  - It comes back to `/connections?connected=<accountId>` or `/connections?error=<code>`.
  - An API-key provider answers 409.
- `POST /bulk-writes/preview {action, channel_account_ids (2 to 100), params?}` answers `{token, expires_at, action, accounts[]}`. Each account has `paused`.
- `POST /bulk-writes/confirm {token}` answers 202 `{action, account_count, queued}`.
  - 404: the token is unknown.
  - 409: the token expired, was used, belongs to another user, or an account left the user's scope.
- Platform:
  - `GET` and `PUT /platform/maintenance {maintenance}` answer `{maintenance, updated_at}`.
  - `GET /platform/api-usage/live` answers `{ebay_budget[], items[]}`. `items` are the usage rows with `updated_at`.

**Status:** `active`, `needs_reauth`, `paused`, `error` or `disconnected`. The server works it out in that reverse order of precedence: disconnected wins, then needs_reauth, then paused, then error.

**Until the server lands, use MSW.** Today the workspace routes answer 404 and the rest 503. They become real like this:
- Connections, authorise and the OAuth return: with T-0701.
- Kill switch, bulk, maintenance and live usage: with T-0702.
