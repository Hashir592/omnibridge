From S2, 17 Nov 2026. Page addresses and API addresses share paths.

The SPA's page paths and the API's paths overlap on `app.omnibridge.co.uk`: `/users` is both the
Users page and `GET /users`; `/users/:userId` is a page and `DELETE /users/:userId`; the API also
has `/access-reviews`. When the web app starts serving the SPA, a reload or typed address on
`/users` would get the JSON list instead of the page.

The demo mock hit exactly this (Hashir saw raw JSON at `/users/access-reviews`); it is fixed in the
mock (document requests pass through) in PR #60. The real server needs a rule. Two options:
- (simple) the web app serves `index.html` to any GET that asks for a document
  (`Sec-Fetch-Dest: document` / `Accept: text/html`), and the API answers only the rest; or
- (cleaner, bigger) the API moves under one prefix such as `/api/` in the contract.

Please rule on it (S3 task for whoever wires the SPA host). Until then nothing is broken: the SPA is
not served by apps/web yet.
