**Desk and labels** (Shipping tab, any user with Shipping ticked, company-scoped):
- `GET /shipping/desk` (`getShippingDesk`): orders awaiting dispatch, sorted by ship-by.
  - Filters: `company_id`, `channel_account_id`, `provider`, `ship_by` (`today`, `overdue`, `tomorrow`), plus `page`/`limit`.
  - Each row has `default_weight_g`, `suggestion` (the rule that chose a carrier and service: show it, and always allow an override, SHP-3), `partial_dispatch` and the order flags. `address_shortened` must be confirmed before labelling.
- `POST /shipping/labels` (`createLabels`): 1 to 200 orders, each with `carrier_account_id`, `service_code`, `parcels[{weight_g}]` (1 to 20), optional `line_ids` (ship some lines now, only where `partial_dispatch` is true) and `confirm_shortened`. It answers 202 with a `LabelBatch`; poll `GET /shipping/batches/{batchId}` until `done`.
  - Each item has a `state` (`queued`, `creating`, `created`, `failed`, `refused`), a `tracking_number`, a `refusal` (a stable code: say it in plain words) and an `error` (`code`, `message`, `fields`).
  - SHIP-4: show the carrier's plain `message` **and** its raw `code`.
- `POST /shipping/labels/print` (`printLabels`) `{shipment_ids}` streams one PDF in the workspace's label format. Nothing is stored; download it at once.
- **Ship together:** `POST /shipping/ship-together` (`shipTogether`) `{group_id, order_ids (2 to 20, all ticked by default), carrier_account_id, service_code, parcels}`.
  - The weight defaults to the members' sum plus one packaging allowance. The service is the highest `rank` any member needs, and the user may override it (C3.4).
  - 409 `order_changed` means a member changed; its detail names the order. Nothing was bought.
- `GET /shipping/shipments/{id}` (`getShipment`): parcels, orders with `cost_share_pence`, `cost_pence` and `label_stored`.
- `POST /shipping/shipments/{id}/reprint` (`reprintShipment`): 200 is the PDF; 202 means it is being fetched again (print once ready). It never buys a new label.
- `POST /shipping/shipments/{id}/void` (`voidShipment`): every order on the label goes back to Awaiting dispatch, and the label joins the reconcile list.
  - 409 `tracking_sent` once tracking has gone to the channel. Say it in plain words: "Tracking was already sent to the channel, so this label can no longer be voided here."
  - The confirm dialog should say Evri has no void, so the label must be reconciled with Evri by hand.
- **Reconcile list:** `GET /shipping/reconcile` (`listReconcile`) and `POST /shipping/reconcile/{parcelId}/done` (`markReconciled`).
  - `reason` `voided`: voided here.
  - `reason` `unknown`: Evri may hold this parcel. Show `client_uid` so it can be found in Evri's My Shipments.
- `POST /orders/{orderId}/address-check` (`confirmAddressCheck`), for the new flag `address_changed_after_label`. Show it as: "The buyer's address changed after the label was printed. The printed label still has the old address. Check it before dispatch." Then add a "Checked" button.
- `POST /shipping/packing-slips` (`packingSlips`) `{order_ids}` streams a PDF. Show it only when `packing_slip_enabled` is on.

**Tracking** (TRK-3):
- `tracking_state` on order rows is now `pending | sent | confirmed | failed`. `not_confirmed` is gone; the 4-hour alert is the `tracking_not_confirmed` flag.
- `GET /orders/{orderId}/tracking` (`listOrderTracking`) lists pushes with `state`, `attempts`, `last_error.code`, `next_attempt_at` and `confirmed_at`.
- `POST /shipping/tracking/{pushId}/resend` (`resendTracking`) is for admins only.

**Settings, rules, carriers:**
- `GET/PUT /shipping/settings`: anyone with Shipping can read it; admins change it. It holds `auto_dispatch_on_label`, `label_format` (THERMAL, DEFAULT, TWO_PER_PAGE, LARGE_SINGLE, LARGE_MULTI), `packaging_allowance_g`, `packing_slip_enabled` and `tracking_hold_minutes` (0 to 240, default 30: until then a void undoes everything).
- `GET/PUT /shipping/rules` (admins change it): the whole ordered list, first match wins.
  - Conditions: `provider`, `channel_account_id`, `company_id`, weight and item-count ranges, `postcode_prefixes` (upper case).
  - Action: `carrier_account_id` + `service_code`.
- `GET /shipping/carriers` (`listCarrierAccounts`): every carrier account any shipping user can ship with, whatever company owns it (SHIP-1), with its `services`.
- **Carrier setup** (Connections, admins):
  1. `GET /connections/evri/authorise-url` gives the Evri page to sign in on.
  2. Tell the admin: "After signing in, Evri sends you to a page that may show an error. Copy the code from the address bar (after `code=`). It works once, within 72 hours."
  3. `POST /connections/evri` `{company_id, display_name, auth_code}` answers 201 with a Connection.
  4. `POST /connections/{accountId}/evri/reauthorise` `{auth_code}` is for an account in `needs_reauth`.
  - `GET/PUT /connections/{accountId}/service-costs` holds cost per service in pence **excluding VAT** plus `vat_rate_bp` (default 2000).
