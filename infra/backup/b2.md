# Backblaze B2 settings for M22 (T-0405, ADR-016)

Written now so the deploy only has to apply them. Region: **EU Central** (SEC-11).
Nothing here is a secret. The keys themselves go in the ops repo's secrets register.

## Buckets

| Bucket                   | Holds                                              | Lifecycle rule (hidden files)  |
| ------------------------ | -------------------------------------------------- | ------------------------------ |
| `omnibridge-backup-main` | db-main dumps and the tombstone journal (IDs only) | `daysFromHidingToDeleting: 14` |
| `omnibridge-backup-pii`  | db-pii dumps (ciphertext)                          | `daysFromHidingToDeleting: 1`  |

Both buckets are private, with no file versioning beyond the lifecycle rules:

```json
{ "fileNamePrefix": "", "daysFromUploadingToHiding": null, "daysFromHidingToDeleting": 14 }
```

```json
{ "fileNamePrefix": "", "daysFromUploadingToHiding": null, "daysFromHidingToDeleting": 1 }
```

## Application keys

| Key                    | Bucket | Capabilities                                    | Where                                                           |
| ---------------------- | ------ | ----------------------------------------------- | --------------------------------------------------------------- |
| `ob-backup-main`       | main   | `listBuckets, listFiles, readFiles, writeFiles` | the server (`backup.sh`)                                        |
| `ob-backup-pii`        | pii    | `listBuckets, listFiles, readFiles, writeFiles` | the server (`backup.sh`)                                        |
| `ob-backup-admin-main` | main   | the above plus `deleteFiles`                    | GitHub Actions `backup-admin` environment only (`retention.sh`) |
| `ob-backup-admin-pii`  | pii    | the above plus `deleteFiles`                    | GitHub Actions `backup-admin` environment only (`retention.sh`) |

What these capabilities mean:

- The server's keys have no `deleteFiles` capability. restic can only hide files, and the lifecycle rule removes them later. That is the ransomware protection.
- `forget`, `prune` and `check` run only from the protected environment.

## Server environment (M22)

```text
RESTIC_MAIN_REPOSITORY=b2:omnibridge-backup-main:restic
RESTIC_PII_REPOSITORY=b2:omnibridge-backup-pii:restic
RESTIC_MAIN_PASSWORD_FILE=/run/secrets/restic_main_password
RESTIC_PII_PASSWORD_FILE=/run/secrets/restic_pii_password
B2_ACCOUNT_ID / B2_ACCOUNT_KEY   the bucket's key, set per run
```

Each repository has its own password and its own key. Never use one key for both buckets.

## Schedule and checks

- **Nightly:** `infra/backup/backup.sh`.
- **Retention:** daily, from `backup-admin`, using `infra/backup/retention.sh`:
  - main: 7 daily, 4 weekly and 6 monthly snapshots
  - PII: 3 daily snapshots
- **Restore drill:** quarterly, using `infra/backup/restore-drill.sh` (AT-24).
- **Alerting (OPS-4):** the backup-age alert reads the newest snapshot time (M22 observability).
